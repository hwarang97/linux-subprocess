# Linux 자식 프로세스 관리자 계획서

## 목적과 배경

현재는 C와 Linux를 막 배우기 시작한 단계이므로, 운영체제가 프로그램을 실행하고 관리하는 방식에 실제로 흥미가 있는지 확인한다. 이 프로젝트는 하드웨어를 직접 제어하는 것이 아니라, Linux 위에서 여러 프로그램을 안전하게 실행·종료·정리하는 소프트웨어를 만들어 보는 첫 실습이다.

C를 사용해 프로세스, 메모리, 운영체제의 역할을 직접 관찰하고, 이후 시스템 소프트웨어·제품 기능 개발을 계속 탐색할지 판단하는 근거로 삼는다.

## 무엇을 만들 것인가

부모 프로그램이 자식 프로그램을 실행하고 관리하는 작은 C 프로그램을 만든다.

- 자식 프로세스를 생성한다. (`fork`)
- 자식 프로세스가 간단한 Linux 명령을 실행한다. (`exec`)
- 부모 프로세스가 자식의 종료를 기다리고, 종료 상태를 출력한다. (`waitpid`)
- `Ctrl+C` 또는 종료 신호를 받으면 자식을 정리하고 프로그램을 종료한다.
- 실행 중인 프로세스와 종료 뒤의 상태를 확인해 좀비 프로세스가 남지 않게 한다.

## 진행 순서

1. WSL2 등 Linux 환경에서 C 프로그램을 컴파일하고 실행한다.
2. `fork`로 부모와 자식 프로세스의 PID를 출력해 둘의 관계를 확인한다.
3. 자식에서 `exec`로 `sleep`처럼 오래 실행되는 간단한 명령을 실행한다.
4. 부모에서 `waitpid`로 자식의 종료와 종료 코드를 수집한다.
5. 신호 처리를 추가해 `Ctrl+C`로 실행 중인 자식을 종료하고 회수한다.
6. `ps`로 실행 전·중·후의 프로세스를 관찰하고, 좀비 프로세스가 생기는 경우와 해결 방법을 기록한다.

## 완료 기준

- 자식 프로세스를 실행하고 정상 종료 또는 강제 종료까지 관리할 수 있다.
- `fork`, `exec`, `waitpid`, 시그널이 각각 왜 필요한지 설명할 수 있다.
- 종료 후 좀비 프로세스가 남지 않으며, 관찰한 점과 재미있었던 점을 짧게 기록한다.

첫 버전이 끝난 뒤에도 흥미가 남으면 `/proc`으로 자원 사용량을 보여 주거나, 파이프를 이용해 부모와 자식이 메시지를 주고받도록 확장한다.
