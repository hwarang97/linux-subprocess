# Linux 자식 프로세스 관리자 구현 계획서

## 목표

부모 프로그램이 자식 프로세스를 만들고, Linux 명령을 실행시키며, 정상 종료와 강제 중단 상황까지 안전하게 관리하는 C 프로그램을 단계적으로 구현한다.

## 구현 단계

### 1단계: Linux와 C 실행 확인

- WSL2 또는 Linux 환경에서 C 파일을 컴파일하고 실행한다.
- 간단한 출력 프로그램으로 `gcc` 빌드와 실행 흐름을 확인한다.

**완료 기준:** C 프로그램을 직접 컴파일하고 실행할 수 있다.

### 2단계: 프로세스 정보 출력

- 현재 프로그램의 PID와 부모 프로세스의 PID를 출력한다.
- 실행 중인 프로그램도 운영체제가 관리하는 프로세스임을 확인한다.

**완료 기준:** 자신의 PID와 부모 PID가 무엇을 의미하는지 설명할 수 있다.

### 3단계: 자식 프로세스 생성

- `fork()`를 호출해 자식 프로세스를 생성한다.
- 부모와 자식이 각자 다른 메시지와 PID를 출력하도록 만든다.

**완료 기준:** 하나의 프로그램 실행이 부모와 자식이라는 두 흐름으로 나뉨을 확인할 수 있다.

### 4단계: 자식에게 Linux 명령 실행시키기

- 자식 프로세스에서 `exec()`를 호출한다.
- `sleep 10`처럼 일정 시간 실행되는 간단한 Linux 명령을 실행한다.

**완료 기준:** 자식 프로세스가 자신의 코드 대신 지정한 Linux 명령을 실행한다.

### 5단계: 부모가 자식 종료 관리하기

- 부모 프로세스가 `waitpid()`로 자식의 종료를 기다린다.
- 자식이 정상 종료했는지와 종료 코드를 출력한다.

**완료 기준:** 부모가 자식의 종료 상태를 회수하며, 좀비 프로세스를 남기지 않는다.

### 6단계: 중단 신호까지 안전하게 처리하기

- `Ctrl+C` 신호를 부모가 받도록 처리한다.
- 부모는 자식에게 종료 신호를 전달한다.
- 부모는 `waitpid()`로 자식을 회수한 뒤 종료한다.
- 다른 터미널에서 `ps`를 사용해 실행 전·중·후 프로세스 상태를 관찰한다.

**완료 기준:** 사용자가 프로그램을 중단해도 자식 프로세스와 좀비 프로세스가 남지 않는다.

## 권장 진행 방식

우선 1~5단계를 첫 번째 완료 목표로 삼는다. 6단계는 신호 처리를 추가하는 확장 단계로 진행한다. 각 단계가 끝날 때마다 실행 결과와 관찰한 내용을 짧게 기록한다.

## 최종 확인 항목

- `fork`, `exec`, `waitpid`, 시그널의 역할을 설명할 수 있는가
- 자식 프로세스가 정상 종료될 때 상태를 확인할 수 있는가
- `Ctrl+C`로 중단해도 자식과 좀비 프로세스가 남지 않는가
